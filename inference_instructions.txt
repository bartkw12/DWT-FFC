Inference on 3080 Ti PC

This file assumes:
- You already have a working Python venv on the 3080 Ti PC.
- Your downloaded model files are already placed in the repo's weights folder on the PC.
- You want to run inference through test.py on one or more hazy images.

What changed in this repo
- test.py now supports single-GPU inference on cuda:0.
- test.py accepts an input folder and a checkpoint path.
- test.py supports arbitrary image sizes by running tiled inference.
- .gitignore now ignores weights/*.pkl and weights/*.pth so local weight files should not be pushed accidentally.

Important note about your local weights
- If your weight files in weights/ are untracked local files, git pull will leave them alone.
- If you ever accidentally added them to git on the PC repo, remove them from the git index once with:
  git rm --cached weights\your_checkpoint.pkl weights\convnext_xlarge_22k_1k_384_ema.pth
- After that, commit the removal if needed. This is only necessary if git status shows those files as tracked.

Recommended folder layout on the PC
- DWT-FFC\weights\convnext_xlarge_22k_1k_384_ema.pth
- DWT-FFC\weights\validation_best.pkl
  or
- DWT-FFC\weights\test_best.pkl
- DWT-FFC\input\your_hazy_image.jpg

Step 1: Open PowerShell in the repo root on the PC
- Expected location example:
  C:\Users\gts\Desktop\Platforms Sandbox\Use Case No37\Use Case No37 Testing\test\Baselines\DWT-FFC

Step 2: Activate the venv
Run:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
& ".\.venv\Scripts\Activate.ps1"

What to expect
- Your prompt should change to show the virtual environment is active.

Step 3: Check your branch and pull the latest repo changes
Run:
git status
git branch --show-current
git pull origin main

What to expect
- You should be on main.
- git pull should bring down the patched test.py and updated .gitignore.
- Your local weights should remain in place if they are untracked.

Step 4: Confirm the key files exist
Run:
Get-ChildItem .\weights
Get-ChildItem .\input

What to expect
- In weights, you should see:
  convnext_xlarge_22k_1k_384_ema.pth
  and at least one generator checkpoint such as validation_best.pkl or test_best.pkl
- In input, you should see your hazy image file.

Step 5: Optional quick environment sanity checks
Run:
python --version
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'NO CUDA')"

What to expect
- torch.cuda.is_available() should print True.
- The device name should show your 3080 Ti.

Step 6: Run inference

Important note about AMP
- Do not use `--amp` as the default command for this model.
- This repo uses FFT-based FFC layers, and on your current PyTorch build they do not support half precision.
- If you use `--amp`, you may see:
  RuntimeError: Unsupported dtype Half
- Use full precision for inference unless you specifically confirm AMP works on your environment.

Option A: Use validation_best.pkl
Run:
python test.py --input_dir .\input --output_dir .\test_result --device cuda:0 --checkpoint .\weights\validation_best.pkl

Option B: Use test_best.pkl
Run:
python test.py --input_dir .\input --output_dir .\test_result --device cuda:0 --checkpoint .\weights\test_best.pkl

What to expect
- The script should print the selected device, checkpoint, input folder, and output folder.
- Then it should print a processing line for each image in input.
- When complete, it should print:
  Inference complete. Saved N image(s).

Step 7: Check the output
Run:
Get-ChildItem .\test_result

What to expect
- You should see one output image per input image.
- Output filenames should match the input base names, saved as .png.

If you want to test with one image first
- Put only one hazy image in .\input
- Then run one of the inference commands above

If you get a CUDA out of memory error
Run again with a smaller tile size:
python test.py --input_dir .\input --output_dir .\test_result --device cuda:0 --checkpoint .\weights\validation_best.pkl --tile_size 768

If that still fails, try:
python test.py --input_dir .\input --output_dir .\test_result --device cuda:0 --checkpoint .\weights\validation_best.pkl --tile_size 512

If you get `RuntimeError: Unsupported dtype Half`
- You are almost certainly still using `--amp` somewhere in the command you ran.
- Remove `--amp` and rerun.
- Correct example:
  python test.py --input_dir .\input --output_dir .\test_result --device cuda:0 --checkpoint .\weights\test_best.pkl

If you get a missing package/import error
- Your PC venv is missing one or more repo dependencies.
- Install the packages you already prepared for that PC environment, then rerun.

If torch reports a CPU-only build
- If `python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"` shows something like `+cpu` and `False`, your PC venv has a CPU-only PyTorch install.
- This is not fixed by editing test.py or pasting CUDA text into the repo.
- The fix is to install a CUDA-enabled PyTorch build in the PC venv.
- Start by checking your Python version:
  python --version
- This repo's PC requirements file is:
  .\requirements-pc-full.txt
- It is written around a CUDA-enabled PyTorch stack and recommends Python 3.8.
- If your venv is Python 3.8 or 3.9, you can usually do:
  pip uninstall -y torch torchvision
  pip install -r .\requirements-pc-full.txt
- Then verify again with:
  python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'NO CUDA')"
- If your venv is Python 3.12 or another newer version, the exact wheels pinned in requirements-pc-full.txt may not exist for that Python version. In that case, create a new venv with Python 3.8 or 3.9 on the PC and install from requirements-pc-full.txt there.
- If your venv is Python 3.10 or newer and `pip install -r .\requirements-pc-full.txt` fails on `torch==1.10.2+cu113`, that usually means the pinned CUDA wheel is not published for your Python version.
- Best course of action:
  create a new Python 3.8 or 3.9 venv on the PC and install from requirements-pc-full.txt there
- This is the most reliable option because it stays closest to the repo's intended runtime.
- Alternative for inference-only:
  keep Python 3.10, install a newer CUDA-enabled torch/torchvision pair manually, then install the remaining non-PyTorch packages separately
- The alternative can work, but it is less predictable than using Python 3.8 or 3.9 with the pinned PC requirements.
- Also check that `nvidia-smi` works in PowerShell on the PC. If it does not, the NVIDIA driver/CUDA runtime setup on the PC needs attention before PyTorch can use the GPU.

If you get a checkpoint not found error
- Check the exact filename in .\weights and update the --checkpoint argument to match it exactly.

If you get an error about the ConvNeXt backbone file
- Make sure this file exists exactly at:
  .\weights\convnext_xlarge_22k_1k_384_ema.pth

If you want to try the script without naming a checkpoint explicitly
- This only works if the script can unambiguously detect a checkpoint in weights.
- Command:
  python test.py --input_dir .\input --output_dir .\test_result --device cuda:0
- If multiple candidate checkpoint files are present, the script will ask you to pass --checkpoint explicitly.

About using hazy images from the internet
- Yes, you can place a hazy RGB image into .\input and the script will push it through the model pipeline.
- Quality is not guaranteed on arbitrary internet images because the model was trained for a specific dehazing setting.
- Start with one reasonably sized JPG or PNG to confirm the pipeline runs.

Minimal run sequence
1. Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
2. & ".\.venv\Scripts\Activate.ps1"
3. git pull origin main
4. Get-ChildItem .\weights
5. Get-ChildItem .\input
6. python test.py --input_dir .\input --output_dir .\test_result --device cuda:0 --checkpoint .\weights\validation_best.pkl
7. Get-ChildItem .\test_result

If something fails
- Copy the full terminal output.
- The most useful things to share are:
  the exact command you ran
  the full error message
  the output of Get-ChildItem .\weights
